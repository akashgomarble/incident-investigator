# Incident investigation report: INC-006
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The quote latency degradation in INC-006 is best explained by H1 (confidence 0.72, medium): an unplanned redis-cache primary failure at 13:22:10Z promoted an EMPTY, still-resyncing replica at 13:22:52Z, which caused a cold-cache miss storm in market-data-service (289 quote rebuilds from the exchange feed, 1.0-8.7s each, from 13:22:25Z) and drove pricing-engine quote computation past its deadline (first error 13:23:57Z, p99 stepping from ~60ms to ~2.2s). The mechanism chain is verified and monotonic across logs (failover -> empty-replica promotion -> miss storm -> first deadline error within 107s), sits inside the 13:16-13:24Z onset bracket, and every tested alternative is contradicted: no deployment or config change on the quote path (including redis-cache itself), pricing-engine CPU flat, and the api-gateway clean. The main residual weakness is that the "market-data-service slow -> pricing-engine deadlines" hop rests on logs, not metrics, because all redis-cache and market-data-service metrics were permanently unavailable (circuit_open), and the "shared" blast radius is only weak-positive from the sparse off-path consumer logs.

## Probable root cause
**redis-cache primary failure promoted an EMPTY replica → cold-cache storm → market-data-service slow → pricing-engine quote deadlines** -- infrastructure_failure in `redis-cache`, triggered by `null` (confidence 0.72, medium)

### H1: redis-cache primary failure promoted an EMPTY replica → cold-cache storm → market-data-service slow → pricing-engine quote deadlines
At 13:22:10Z the redis-cache primary redis-cache-2 failed three consecutive PING health checks and was marked down; failover promoted replica redis-cache-3, which was still resyncing and therefore EMPTY (13:22:52Z). redis-cache is the only shared=true node on the quote path, consumed as kind='cache' by both market-data-service and pricing-engine (F3, F28). Later reconnect storms and full resyncs (13:28–13:40Z) are sustainers, not the onset mechanism. The chain is now a monotonic, verified 107-second log sequence (failover → empty-replica promotion → miss storm → first deadline error) sitting inside the 13:16–13:24Z onset bracket.
