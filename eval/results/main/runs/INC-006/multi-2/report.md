# Incident investigation report: INC-006
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The incident is a redis-cache infrastructure failure: at 13:22:10Z the primary node redis-cache-2 failed health checks and was marked down, and the 13:22:52Z failover promoted replica redis-cache-3, whose dataset was EMPTY because it was still resyncing (F29/F32/F33). The promoted primary therefore served a cold keyspace — hit_ratio collapsed ~96% -> 13% and memory_pct collapsed ~69% -> ~7% while evictions and CPU stayed flat (F21/F25/F26/F27/F28/F34) — and market-data-service entered a synchronous 'quote:* cache miss storm' rebuilding entries from the exchange feed snapshot (up to 8748ms), inflating its p99 to ~1433ms (F10/F11). pricing-engine synchronously calls market-data-service, so it inherited that latency and emitted 192 'quote computation deadline exceeded: market-data-service took <n>ms' errors, producing the 2-3s quote loads (F7/F9). Confidence on this root cause is high (0.82), capped below 0.9 by one unexplained asymmetry: auth-service is also a redis-cache client yet shows no latency step (F20), and cross-keyspace coldness is unobservable in this telemetry (F36). The origin is redis-cache infrastructure, not pricing-engine and not any deployment; degradation is still ongoing at 14:56Z (F8).

## Probable root cause
**redis-cache primary failed and failover promoted an EMPTY replica (cold/empty keyspace) → miss storm → quote latency** -- infrastructure_failure in `redis-cache` (confidence 0.82, high)

### H1: redis-cache primary failed and failover promoted an EMPTY replica (cold/empty keyspace) → miss storm → quote latency
At ~13:20-13:22Z the redis-cache primary (redis-cache-2) failed health checks (3 consecutive PING timeouts) and was marked down; the failover promoted replica redis-cache-3, whose dataset was EMPTY because it was still resyncing. The promoted primary therefore served a cold/empty keyspace: hit_ratio collapsed from ~95% to ~13-39% and memory_pct collapsed from ~69% to ~7% (dataset wiped, not exhausted), with evictions and CPU flat. market-data-service then entered a 'cache miss storm', synchronously rebuilding quote:* entries from the exchange feed snapshot (up to 8748ms), which inflated its p99 to ~1433ms. pricing-engine synchronously calls market-data-service over HTTP, so it inherited that latency and emitted 'quote computation deadline exceeded: market-data-service took <n>ms' errors, producing 2-3s quote loads. Origin is redis-cache infrastructure, not pricing-engine, and not any deployment.
