# Incident investigation report: INC-011
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The order-service quote timeouts are caused by pricing-engine CPU saturation triggered by config change cfg-3120, which ramped the flags.pricing.greeks_v2.rollout_pct experiment flag from 5 to 100 at 2026-05-20T12:04:00Z (confidence 0.82, high). In the very next minute bucket, pricing-engine CPU stepped 38.22% -> 98.65% and p99 stepped 60.53ms -> 2534.9ms, while offered load stayed flat (~590-687 req/s), so per-request compute cost rose rather than traffic; order-service's only error type is a 2500ms timeout waiting on pricing-engine (first at 12:06:10Z), and the dominant pricing-engine signature is an internal GreeksV2 Monte-Carlo deadline. Competing hypotheses are refuted by data: traffic-driven saturation (flat request_rate), the reporter's market-data-service protobuf deploy (9 minutes before onset, service flat, no parse errors), and a shared redis-cache/infra disturbance (all cache health proxies flat, no IO/connection errors). The one non-verified link is the mechanism (flag ramp -> the measured saturated CPU being the Greeks v2 code path); no per-flag metric exists in this dataset, so it is declared as an assumption rather than proven.

## Probable root cause
**Greeks v2 flag ramp to 100% saturates pricing-engine CPU** -- config_change in `pricing-engine`, triggered by `cfg-3120` (confidence 0.82, high)

### H1: Greeks v2 flag ramp to 100% saturates pricing-engine CPU
cfg-3120 ramped pricing-engine's flags.pricing.greeks_v2.rollout_pct from 5 to 100 at 12:04:00Z, so the GreeksV2 Monte-Carlo calculator (paths=20000) now runs on essentially all quote requests. This raised per-request compute cost with offered load unchanged, stepping pricing-engine CPU from flat ~40% to ~99-100% in the single minute bucket 12:05:00Z and inflating its p99 from ~60ms to ~2535ms in the SAME minute. order-service's quote call to pricing-engine then exceeded its 2500ms budget, producing 'quote call timed out after 2500ms' errors. Fault origin: a config/flag change in pricing-engine (not a code deploy, not a redis/infra event).
