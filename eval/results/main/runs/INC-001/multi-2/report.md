# Incident investigation report: INC-001
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The SEV-1 spike in HTTP 500s on POST /v1/orders was caused by dep-5101, the 12:10:00Z deployment of order-service v2.14.0, which introduced a new MarginCheckValidator into the order validation chain for F&O orders. For derivatives orders the new validator dereferences a null marginProfile and throws NullPointerException at MarginCheckValidator.java:88, failing the request with HTTP 500. Confidence is high (0.85 per reviewed ranking, critic-raised to 0.90): the untruncated error set partitions exhaustively into 103 MarginCheckValidator NPEs + 88 "marginProfile is null" rejections, all 100% orderType=FNO with zero CASH/EQUITY signatures, and onset (12:10-12:11Z bucket, first ERROR 12:12:31Z) falls 1-2 minutes after the deploy with no other change in the window. Alternative dependency, saturation and config causes are each contradicted by direct evidence (flat latency and resources, zero downstream WARN+, off-path config change). The deploy was atomic with no canary stages, no feature flag, and has not been rolled back as of 13:59Z.

## Probable root cause
**dep-5101 introduced a broken F&O margin validation path yielding NPE on FNO orders** -- bad_deployment in `order-service`, triggered by `dep-5101` (confidence 0.85, high)

### H1: dep-5101 introduced a broken F&O margin validation path yielding NPE on FNO orders
order-service v2.14.0 (dep-5101, deployed 12:10:00Z) replaced legacy OrderRules.validateMargin() with a new MarginCheckValidator in the validation chain. For derivatives (FNO) orders the new validator dereferences a null marginProfile and throws NullPointerException at MarginCheckValidator.java:88, so the request fails with HTTP 500. Cash/equity orders never traverse this FNO branch, so the blast radius is derivatives-only. The fault originates in the deployed order-service release, not in any dependency. Residual uncertainty is confined to the exact origin of the null marginProfile (own code vs. an uninspected upstream supplier) and to rollout-completion timing; neither changes the top ranking.

**Causal chain**
1. dep-5101 deploys order-service v2.14.0 at 12:10:00Z, adding MarginCheckValidator to the validation chain and removing legacy OrderRules.validateMargin(); it is the only deployment across all services in the window, with no rollout/canary stages. [F1, F2, F18]
2. The new validator is on the order-placement path and is reached only for F&O (derivatives) order types; it is not feature-flag-gated and no flag service exists in the topology. [F1, F14, F19, F20]
3. marginProfile is null for the offending accounts, so MarginCheckValidator.validate dereferences null at line 88 and raises NullPointerException (the data supplier of marginProfile was not inspected). [F9, F14, F24]
4. The NPE surfaces as an order rejection / HTTP 500: the untruncated 191-entry ERROR set partitions exhaustively into 103 FNO MarginCheckValidator NPEs + 88 'order rejected with 500: marginProfile is null'. [F24, F9]
5. order-service 5xx error rate steps from ~0.2% to ~18% at the 12:10-12:11Z buckets, 1-2 minutes after the deploy, matching the first ERROR log at 12:12:31Z; onset is pinned to 12:10-12:11Z, not the earlier cfg-2101 minute. [F7, F8, F14, F16, F27]
6. Failures are 100% FNO: filtering ERROR entries by orderType=CASH and orderType=EQUITY both return 0, so cash/equity orders are genuinely unaffected, matching the deploy's stated F&O scope. [F25, F24, F14]
7. api-gateway error rate rises in the same window by roughly an order of magnitude less, consistent with it merely relaying failing order traffic. [F11]
8. No dependency-side fault is present: exchange-gateway and pricing-engine show zero WARN+ logs in 11:55-12:25Z over complete ranges, and pricing-engine/payment-service/settlement-service/user-db error rates and latency are flat through onset. [F15, F30, F28, F29, F31, F32]
