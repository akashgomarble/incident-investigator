# Incident investigation report: INC-006
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The root cause is a redis-cache internal primary failure: redis-cache-2 failed three consecutive PING health checks at 13:22:10Z and the platform promoted replica redis-cache-3, whose dataset was explicitly EMPTY because it was still resyncing (13:22:52Z, F34). That emptied the shared cache, forcing market-data-service to rebuild nearly every quote from the exchange feed snapshot (1-7s per request, F28); with request volume unchanged (F25/F26) this extra per-request work drove market-data-service CPU from ~45% to ~90% (F14) and its p99 from ~40ms to ~1.9s (F10/F15), which pricing-engine then hit synchronously, breaching its deadline and pushing p99 >2s up through api-gateway to the trading screens (F7/F9/F11). All competing hypotheses are contradicted by direct telemetry: market-data request_rate is flat at onset (F25/F26), pricing-engine CPU is unsaturated (F12), exchange-gateway latency is flat (F16), redis evictions did not spike (F31), and no deployment or config change preceded onset (F1/F2/F3/F19-F22). Confidence is medium (0.72), capped because the miss-storm→CPU-saturation hop is inferred from co-timing plus log text rather than a controlled pre/post comparison, and the sub-cause of redis-cache-2's PING failure is not captured by any telemetry.

## Probable root cause
**redis-cache internal primary failure -> empty-replica failover -> cache-miss storm -> market-data-service CPU saturation -> pricing-engine deadline breaches** -- infrastructure_failure in `redis-cache`, triggered by `null` (confidence 0.72, medium)

### H1: redis-cache internal primary failure -> empty-replica failover -> cache-miss storm -> market-data-service CPU saturation -> pricing-engine deadline breaches
The redis-cache primary node (redis-cache-2) failed health checks (3 consecutive PING timeouts) and was marked down at 13:22:10Z; the platform promoted replica redis-cache-3, whose dataset was EMPTY because it was still resyncing (13:22:52Z). That emptied the shared cache. market-data-service, a redis-cache consumer, then had to rebuild nearly every quote from the exchange feed snapshot ('cache miss storm: quote:<n> not in redis-cache, rebuilding from exchange feed snapshot (<n>ms)'), which is 1-7s of extra work per request. Because request volume was unchanged, that per-request recomputation drove market-data-service CPU from ~45% to ~90-94%, inflating its p99 from ~40ms to ~1.9s. pricing-engine calls market-data-service synchronously and breached its own deadline ('quote computation deadline exceeded: market-data-service took <n>ms'), pushing pricing-engine p99 >2s and api-gateway p99 up to the trading screens. No human-initiated change triggered this: no deployment to pricing-engine/market-data-service/redis-cache/exchange-gateway, and no config change anywhere in the window.
