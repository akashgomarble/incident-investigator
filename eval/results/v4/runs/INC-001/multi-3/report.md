# Incident investigation report: INC-001
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The SEV-1 500s on POST /v1/orders are best explained by a bad deployment: order-service v2.14.0 (dep-5101), deployed 12:10Z, whose new MarginCheckValidator throws a NullPointerException at MarginCheckValidator.java:88 on the F&O (derivatives) margin-check path. Every hop up to the code boundary is verified: dep-5101 is the only F&O-related change in 48h (F2, F3, F21, F34); the 5xx rate steps from ~0.2% baseline in the 12:08Z bucket to ~18% in the 12:12Z bucket (F7, F26); the first error is the NPE with orderType=FNO (F8, F10); failures are deterministic and FNO-only across 426 identical-signature errors over ~106 minutes (F9, F27); and no dependency, shared datastore, or resource metric shows any discontinuity aligned to the onset (F11–F15, F18, F29, F37–F40). Confidence is 0.67 (medium): the single unverified hop is the mechanism (whether the new validator dropped a null guard vs. merely being first to dereference an already-null value), and the competing upstream-data origin (H2, 0.15) was excluded negatively rather than positively refuted. That hop does not change the remedy: roll back or fix dep-5101. The release is still live (not rolled back) and the error rate remains elevated at 13:59Z (18.69%), so the incident is ongoing.

## Probable root cause
**order-service v2.14.0 (dep-5101) MarginCheckValidator regression — new F&O margin-check path throws NPE on null marginProfile** -- bad_deployment in `order-service`, triggered by `dep-5101` (confidence 0.67, medium)

### H1: order-service v2.14.0 (dep-5101) MarginCheckValidator regression — new F&O margin-check path throws NPE on null marginProfile
order-service v2.14.0 (dep-5101, deployed 12:10Z) added a new MarginCheckValidator to the validation chain and removed the legacy OrderRules.validateMargin(). On the F&O (derivatives) path the new validator dereferences marginProfile at MarginCheckValidator.java:88 and throws a NullPointerException when marginProfile resolves null, surfacing as HTTP 500 on POST /v1/orders. Only F&O order types enter this new path, so failures concentrate on derivatives orders. The fault ORIGINATES in the release: no FNO-path failures exist before 12:10Z and the 5xx rate is at baseline in the 12:08Z bucket, then steps to ~18% in the 12:12Z bucket. The open mechanism detail — whether the new validator dropped a null guard the legacy path had, vs. merely being the first code to dereference an already-null value — is a mechanism detail of the SAME origin (the v2.14.0 margin-check change) and does not change the fix (roll back / fix dep-5101). Confidence held below 0.75 because the mechanism hop is assumption-backed (no code access, F19) and H2's origin was excluded only negatively, not positively refuted.
