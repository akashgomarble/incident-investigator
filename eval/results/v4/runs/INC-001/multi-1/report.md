# Incident investigation report: INC-001
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The 500s on POST /v1/orders are best explained by a bad deployment: order-service v2.14.0 (dep-5101, live at 12:10:00Z) added a new F&O MarginCheckValidator that raises a local NullPointerException on the missing 'marginProfile' field, rejecting derivatives (orderType=FNO) orders. The error-rate step is sharply pinned at 12:12:00Z (baseline ~0.1-0.3% to ~18%), the 426 ERROR log lines contain exactly two signatures, both FNO-scoped validator NPEs / marginProfile-null 500s with zero equity-path errors, and p99 latency is flat — a fast local failure, not a timeout-shaped dependency fault. Downstream/shared components (pricing-engine, exchange-gateway, portfolio-service) are flat across onset and no change exists on that path; api-gateway's 10x step is the propagating upstream. Confidence in the top hypothesis is medium (0.68), capped by the unverified exact mechanism (missing null guard vs. a field the removed legacy path used to populate) and the 2-minute deploy-to-onset gap.

## Probable root cause
**dep-5101 (order-service v2.14.0) introduced a defective MarginCheckValidator causing NPE on F&O orders** -- bad_deployment in `order-service`, triggered by `dep-5101` (confidence 0.68, medium)

### H1: dep-5101 (order-service v2.14.0) introduced a defective MarginCheckValidator causing NPE on F&O orders
order-service v2.14.0 (dep-5101, deployed 12:10:00Z) added a new MarginCheckValidator to the validation chain for F&O orders and removed the legacy OrderRules.validateMargin(). The new F&O margin-check code path raises a NullPointerException at MarginCheckValidator.java:88 because marginProfile is null, so derivatives (orderType=FNO) orders are rejected with HTTP 500. The fault ORIGINATES in the newly shipped order-service code path: whether the null is due to a missing guard in the new code or to the new path reading a field the legacy path never loaded, both readings point to the same origin (the dep-5101 code change) and the same fix locus. This is a bad_deployment, not a dependency failure.

**Causal chain**
1. dep-5101 deploys order-service v2.14.0 at 12:10:00Z, injecting a new MarginCheckValidator and removing legacy OrderRules.validateMargin(); it is the only order-service change in the window and the only change within 2 minutes of onset [F1, F13, F14]
2. The new validator executes specifically on the F&O (derivatives) order path and throws NPE when marginProfile is null at MarginCheckValidator.java:88 [F1, F9, F6]
3. The NPE is raised locally inside order-service's own class ('marginProfile is null for account <n>'), not from any remote/transport call [F9, F11, F25]
