# Incident investigation report: INC-006
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The quote-latency degradation in INC-006 was caused by a failure of the redis-cache primary (redis-cache-2) at 13:22:10Z and a failover to a replica (redis-cache-3) whose dataset was empty because it was still resyncing (13:22:52Z). The shared cache tier lost its quote working set — hit_ratio collapsed 95.9%→10.82% in a single 120s bucket and memory_pct fell ~69%→7% — which drove market-data-service into a cache-miss storm rebuilding every quote from the exchange feed (p99 36-45ms → 1916.65ms, CPU ~45% → 81.6%), and pricing-engine then exceeded its computation deadline on those HTTP quote calls (5171-8456ms; p99 ~55-66ms → ~2251ms; ~4% error plateau), producing the user-visible 2-3s quote loads. pricing-engine is a victim, not the origin: its CPU stayed flat ~40% and the dominant error names market-data-service as the slow dependency. Competing explanations are contradicted by measurement — no traffic spike (request_rate flat ~951 req/s), no memory/CPU pressure on the cache (flat evictions and ~22% CPU), and the only in-window change (auth-service v7.2.0 at 11:30Z) is off pricing-engine's dependency graph and ~1h52m before onset. Confidence is high (0.86), with the ultimate trigger of the redis-cache-2 PING/health-check failure remaining unknown due to permanent tooling limits.

## Probable root cause
**redis-cache primary failure → empty-replica failover → cold cache → market-data-service cache-miss storm → pricing-engine deadline-exceeded** -- infrastructure_failure in `redis-cache`, triggered by `null` (confidence 0.86, high)

### H1: redis-cache primary failure → empty-replica failover → cold cache → market-data-service cache-miss storm → pricing-engine deadline-exceeded

The tier therefore lost its quote working set: hit_ratio_pct collapsed 95.9% → 10.82% inside one 120s bucket and memory_pct halved from ~69% to 7% at 13:24Z — direct metric confirmation that the dataset was emptied, independent of the redis log text. market-data-service, which reads the shared cache, began rebuilding every quote from the exchange feed snapshot ('cache miss storm', first_seen 13:22:25Z), and its own latency_p99 stepped from a 36-45ms baseline to 1916.65ms (max 1979.98) in the 13:22:00Z bucket, with its CPU stepping from ~45% to 81.6% (max 94.5). pricing-engine, which calls market-data-service over HTTP for quotes, then exceeded its computation deadline ('market-data-service took 5171-8456ms', first_seen 13:23:57Z), producing the p99 step from ~55-66ms to 1143→2251ms and the ~4% error plateau matching the user-visible 2-3s quote loads. The fault originates in the redis-cache tier; pricing-engine is a victim.
