# Incident investigation report: INC-003
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
The order-submit failures are caused by degradation of the external exchange partner api.exchange-partner.example, reached via exchange-gateway (H1, confidence 0.72, medium). exchange-gateway's outbound calls to that host began timing out at ~10:58-11:01Z (upstream latency ~75x step, error rate stepping to ~44-48%), its circuit breaker tripped at 11:03:26Z, and order-service's placeOrder path then returned 504s at ~31% with a ~30x p99 step. The reporter's deploy hypothesis is decisively excluded: order-service v2.15.2 was rolled back at 11:16Z and the failure persisted unchanged (~31% error, ~5000-5400ms p99) for ~96 minutes afterwards, and the gateway's degradation started before order-service's first error and includes 146 op=quoteSnapshot timeouts that do not originate from the order-submit path. Shared-component exhaustion (H4) and the pricing-engine config change (H3) are rejected on direct metric flatness and timing, respectively. Confidence is medium rather than high because the partner itself has has_telemetry:false, so the conclusion rests on exclusion of internal causes plus log attribution rather than positive partner-side evidence.

## Probable root cause
**External exchange partner (api.exchange-partner.example) degradation is the root cause** -- dependency_failure in `api.exchange-partner.example (external exchange API, via exchange-gateway)`, triggered by `null` (confidence 0.72, medium)

### H1: External exchange partner (api.exchange-partner.example) degradation is the root cause
The external exchange API reached via exchange-gateway began timing out/returning 503 at ~10:58-11:01Z (op=placeOrder and op=quoteSnapshot). exchange-gateway's calls to it fail, its upstream_latency blows up ~75x, its circuit breaker trips, and order-service's placeOrder path (which calls exchange-gateway) then returns 504s at ~31%. Negative evidence is now exhaustive across the internal change surface: the only recorded deploy (order-service v2.15.2, rolled back 11:16Z) and the only recorded config change (cfg-2290, 100 min pre-onset) are both excluded by timing/persistence; and exchange-gateway's entire ERROR stream is attributed to the single external host api.exchange-partner.example (all 309 WARN+ matches, 163 placeOrder + 146 quoteSnapshot; zero other host values; zero 'upstream error' matches). The residual gateway error rate (~44% vs ~31%) is explained by the gateway offering in additional traffic (quoteSnapshot) that order-service does not consume.

**Causal chain**
1. External exchange partner API degrades at ~10:58-11:00Z (connect timeouts, then 503s); the vendor-side event is invisible to telemetry (has_telemetry:false) [F4, F18, F27, F28]

3. exchange-gateway latency p99 steps ~129ms -> ~4528ms (log-scan-independent metric: upstream_latency_ms 117-122ms -> ~8900-9750ms, ~75x) and error rate ~0.2% -> ~38.6% (upstream_error_rate 0.29-0.31% -> 44-48%); circuit breaker OPEN for exchange-api at 11:03:26Z with failure ratio 0.47 [F4, F6, F27, F28]
4. order-service's placeOrder path (downstream http edge to exchange-gateway) times out; all 349 order-service ERROR logs are the single signature 'exchange-gateway call failed: 504 Gateway Timeout (placeOrder)' [F3, F10]

### H3: pricing-engine config change cfg-2290 (shorter quote cache TTL) is the trigger

**Causal chain**
1. pricing-engine config cfg-2290 changed cache.ttl_seconds 5 -> 4 at 09:20Z, cutting quote cache hit rate [F9]
2. Higher miss rate drives more pricing-engine calls to market-data-service and redis-cache, adding latency *(assumed)*
3. order-service's pricing call path slows, contributing to p99 and 504s *(assumed)*
4. order-service error rate steps ~31% at the 11:00Z bucket [F1]
