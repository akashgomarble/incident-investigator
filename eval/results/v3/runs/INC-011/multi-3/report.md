# Incident investigation report: INC-011
*System: multi_agent | outcome: **root_cause_identified** | ended: critic_accepted*

## Summary
Root cause: the pricing-engine feature-flag ramp flags.pricing.greeks_v2.rollout_pct 5→100 (cfg-3120, 2026-05-20T12:04:00Z) sent all quote traffic through the expensive GreeksV2 Monte-Carlo path, turning pricing-engine CPU-bound. CPU stepped from a flat ~40% baseline to a 99–100% sustained plateau from 12:03/12:04 onward while request_rate stayed flat (~645 req/s), p99 went ~60ms→~2.6s and the 2000ms quote budget started being exceeded; order-service, calling synchronously with a 2500ms timeout, then failed 225 quotes with a single timeout signature, error_rate 0.2%→8.04%, p99 160ms→~2840ms. Confidence is medium (0.72, capped at 0.80 by the Critic) because the per-request cost jump is inferred from the flag key/description naming the exact slowed code path (GreeksV2Calculator) plus the CPU-step coincidence rather than an A/B measurement. Competing hypotheses are contradicted by complete telemetry: no throughput step (H4 capacity), and redis-cache flat across all five series with zero WARN logs (H2). The reporter's suspected market-data-service protobuf deploy is downstream with no degradation, 25 minutes before onset and never rolled back (H3 rejected).

## Probable root cause
**Greeks v2 feature-flag ramp to 100% made pricing-engine's quote path CPU-bound and too slow, timing out order-service** -- config_change in `pricing-engine`, triggered by `cfg-3120 / flags.pricing.greeks_v2.rollout_pct 5→100 at 2026-05-20T12:04:00Z` (confidence 0.72, medium)

### H1: Greeks v2 feature-flag ramp to 100% made pricing-engine's quote path CPU-bound and too slow, timing out order-service
A feature-flag config change on pricing-engine (flags.pricing.greeks_v2.rollout_pct 5→100 at 12:04:00Z by pm-experiments, cfg-3120) sent all quote traffic through the new GreeksV2 Monte-Carlo greeks path. That path is far more expensive per call, so pricing-engine CPU stepped from a flat ~40% baseline to ~99% saturation within the same 12:03–12:04 bucket as the ramp, its p99 jumped from ~60ms to ~2.6s, and its own 2000ms quote budget began being exceeded. order-service, which calls pricing-engine synchronously with a 2500ms timeout, then failed quotes with 'pricing-engine quote call timed out after 2500ms'. Throughput is unchanged (request_rate flat ~645 req/s), so this is not a volume-driven event — it is a per-request cost increase on the pricing-engine itself.

**Causal chain**
1. pricing-engine feature flag flags.pricing.greeks_v2.rollout_pct was ramped 5→100 at 12:04:00Z (single atomic cfg-3120 event, author pm-experiments, 'Ramp Greeks v2 experiment to all traffic'), routing 100% of quote traffic through the GreeksV2 code path [F2, F13, F24, F17]
2. The GreeksV2 Monte-Carlo greeks path is far more CPU-expensive per request than the previous path, so pricing-engine CPU steps from ~40% to 99% saturation at 12:03–12:04 — the same bucket as the ramp, and not earlier (12:02 bucket at 120s resolution is still baseline avg 40.13) [F18, F19, F9]
3. With CPU pinned at ~99% (sustained 12:06–13:00, no decay), the GreeksV2 computation runs slow: pricing-engine logs 'GreeksV2Calculator: Monte-Carlo paths=20000 took 6465ms' from 12:05:21Z and 'request deadline exceeded computing quote (2000ms budget)' from 12:06:41Z [F9, F21]
4. pricing-engine p99 latency jumps from flat ~60ms to ~2600–2700ms and stays there, so its own 2000ms quote deadline is exceeded [F7]
5. order-service calls pricing-engine synchronously with a 2500ms timeout; the now-slow quotes trip that timeout, producing all 225 errors as the single pattern 'pricing-engine quote call timed out after 2500ms' from 12:06:10Z; order-service error_rate 0.2%→8.04%, latency_p99 160ms→~2840ms [F4, F8, F22]
