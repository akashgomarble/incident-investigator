# Incident investigation report: INC-007
*System: multi_agent | outcome: **inconclusive** | ended: critic_accepted*

## Summary
The 36% 401-invalid_token failure rate that began as a clean step at 2026-04-15T14:02Z is best explained by the auth-service v7.3.0 release dep-5710 (jjwt 0.11->0.12 parser API break + TokenValidator rewrite) landing at 14:00Z, but this remains below the confidence threshold (top hypothesis 0.48, low). Two auth-service changes landed within 60 seconds of each other and of the onset — dep-5710 at 14:00Z and the signing-key rotation cfg-2705 at 14:01Z — and neither was rolled back, so change history alone cannot attribute the failure. H2 is favored only by symptom shape (fast, in-process failures with flat traffic/latency/CPU/rate-limiting and a stable ~1/3 partial failure), while its decisive hop (the rewritten validator rejecting a deterministic token subset) is inferred, not proven, because auth-service logs are unsearchable (identity-namespace pipeline down). We recommend treating this as a genuine fork: verify the code path first via a canary/rollback test, with the key-id repin (cfg-2705) as the alternate.

## Probable root cause
**Inconclusive** -- the evidence does not single out one cause. See ranked hypotheses and data gaps.

### H2: JWT library upgrade in dep-5710 (jjwt 0.11->0.12, TokenValidator rewrite) regressed validation for a subset of tokens

Origin: the auth-service code release.
